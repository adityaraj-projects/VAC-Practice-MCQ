02  ·  HTTP METHODS
GET vs POST
The form's method attribute decides how data travels to the server.
GET
• Appends data to the URL as a query string
• Visible in the address bar & browser history
• Data length is limited
• Best for search, filters, navigation
• Safe to bookmark or refreshPOST
• Sends data in the request body
• Not visible in the URL
• No practical size limit
• Best for login, registration, uploads
• Not cached or bookmarked by default

04  ·  VALIDATION
Input Validation
Never trust submitted data —validate on the server even if the browser already checked it.
Client -Side
• HTML attributes: required, type, pattern, maxlength
• Instant feedback, better UX
• Easy to bypass —not a security controlServer -Side
• Checked in the Flask route on every request
• Validates presence, type, length, format
• The only validation that can be trusted
Common checks: required fields  ·  data type  ·  length limits  ·  email/pattern format  ·  file type & size

04  ·  VALIDATION
Server -Side Validation Example
@app.route("/register", methods=["POST"])
def register():
errors = []
name = request.form.get("username", "").strip()
email = request.form.get("email", "").strip()
age = request.form.get("age", "")
if not name or len(name) < 3:
errors.append("Username must be at least 3 characters")
if "@" not in email:
errors.append("Enter a valid email address")
if not age.isdigit() or not (0 < int(age) < 120):
errors.append("Age must be a number between 1 and 119")
if errors:
return render_template("register.html", errors=errors)
save_user(name, email, age)
return redirect("/success")

KEY TAKEAWAYS
Summary
HTML forms collect user input and submit it via GET or POST
GET sends data in the URL; POST sends it in the request body
request.form, request.args, and request.files read submitted data
Uploads need multipart/form -data and secure_filename() before saving
Always validate on the server —client -side checks can be bypassed
